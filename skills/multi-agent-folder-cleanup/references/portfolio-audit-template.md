## Entrypoint matrix

Derive the expected set from owner instructions. Do not impose names that the project does not require.

| Project | AGENTS | README_FIRST | Roadmap/status | Authority map | Index | Quick context | Journal | Chat index |
|---|---|---|---|---|---|---|---|---|

Allowed values: opened; listed; path-validated search result; missing by direct listing; alternate name; unverified.

Classification: identical duplicate; intentional pointer; divergent competing control; likely same claim family; unverified.

## Portfolio-level controls

List indexes, manifests, review decks, status summaries, and authority maps outside individual project roots. Flag numbered copies, `.orig` files, and same-date variants until compared.

## Rejected search results

| Query target | Returned path | Reason rejected |
|---|---|---|

Use this whenever enterprise search returns a plausible file from the wrong project.

## Priority findings

1. Divergent controls across roots
2. Missing required entrypoints
3. Cross-project search contamination
4. Stale indexes or manifests
5. Same-name files with unclear canonical status
6. Generated state overwhelming search
7. Oversized journals

## Mixed-scope disclosure

If the request also asks for research, data intake, software changes, or production work, split the report into cleanup and domain-work tracks. Folder authority does not grant permission to promote domain data or change production systems.

## Additive intake tracking

Record the exact incoming/quarantine destination; expected-file manifest and visible post-upload count; non-governing label; privacy exclusions; duplicate and claim-family status; separately authorized navigation/journal updates; and that accepted evidence and authority were unchanged.

## Limitations

State every unavailable check, including hashes, hydration, OS path length, reparse points, unopened archives, inaccessible roots, and live repository or deployment state.
